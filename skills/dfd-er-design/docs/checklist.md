# Checklist ก่อนส่ง และบทเรียนจากงานจริง

## A. ตรวจตรรกะ (ทำก่อนวาด)

รัน `python templates/tools/check_spec.py spec.json dd.json` แล้วอ่านผลทุกบรรทัด

- [ ] **CRUD matrix** (process × store): ทุก store มี W (สร้าง) อย่างน้อย 1 และ R อย่างน้อย 1
- [ ] ไม่มี store ที่ถูกอ่านก่อนถูกสร้างตามลำดับ process (Master → Transaction → Report)
- [ ] **ไล่ข้อมูลตั้งแต่ต้นจนจบ (end-to-end)** อย่างน้อย 3 เส้น เช่น
      ผู้ดูแลระบบ → 1.0 → D1 → 5.0 → D5 → 6.0 → D6 → 8.0 → รายงานของผู้จัดการ ต้องต่อกันได้ไม่ขาด
- [ ] ทุกข้อใน **วัตถุประสงค์และขอบเขต** มี process รองรับ และทุก process ตอบวัตถุประสงค์อย่างน้อย 1 ข้อ
- [ ] สถานะเป็นข้อมูล (ตาราง lookup) ไม่ใช่ process
- [ ] ค่าที่มีคนกำหนด (KPI/เกณฑ์) มี process + store ของตัวเอง และ process ที่ใช้อ่านจาก store นั้น
- [ ] ประวัติเก็บเฉพาะที่ต้องใช้ (ค่าก่อนหน้า ค่าใหม่ เวลา) ไม่มีวันเริ่ม/สิ้นสุดที่ไม่มีใครใช้
- [ ] ไม่มี Black hole / Miracle / Gray hole / Entity↔Store / Store↔Store / Entity↔Entity
- [ ] Level 2 สมดุลกับ Level 1 และ Context สมดุลกับ Level 1
- [ ] **ไม่มีตารางหรือฟิลด์กำพร้า**: ทุกตารางอยู่ใน store, ทุกฟิลด์มี process ที่เขียนและมีที่ใช้ (รายงาน เงื่อนไข หรือ FK)
- [ ] FK ทุกตัวมีเส้นใน ER และทุกเส้นมี FK; 1 เส้นต่อคู่ตาราง
- [ ] cardinality ถามผู้ใช้แล้ว ไม่ได้เดา

## B. ตรวจรูป (หลังวาด)

- [ ] `build.py` รายงาน overlap / cross / through_shape / label_hits / label_label = 0 ทุกรูป ไม่มีข้อยกเว้น
- [ ] `tools/check_vsdx.py *.vsdx` ผ่าน: DisplayMode = 1 ทุก group, ER 1 เส้นต่อคู่, **ไม่มีปลายเส้นลอย/ไม่ glue/ไม่อยู่บนขอบรูป**, store/entity ไม่เกิน 2 กล่อง และกล่องซ้ำมีขีดซ้ำ, **`crossings=0` ไม่มีเส้นตัด/แตะกัน ไม่มีเส้นผ่านกล่องหรือป้าย**
- [ ] entity ฝั่งซ้ายเป็นกล่องเดี่ยว (WARN ซ้ำต้องอธิบายได้ว่าสลับกันจนตัด) และหัวลูกศรขนาดเล็ก
- [ ] layout column-rails: ใช้ `check_vsdx.py --max-copies 0` (ซ้ำกล่องได้) แต่ยังต้อง crossings=0 และกล่องซ้ำมีขีดซ้ำ
- [ ] เปิด PNG ซูมดูทุกส่วน: ไม่มีเส้นตัด ไม่มีเส้นค่อม (line jump) เส้นอ้อมไปด้านหลังแทน
- [ ] อ่าน WARN จำนวน store/entity ที่ซ้ำ: ทุกตัวที่ซ้ำต้องอธิบายได้ว่าถ้าไม่ซ้ำจะเกิดเส้นตัด/เส้นยาว/รก
- [ ] Context: ลูกศรทุกเส้นติดขอบกล่อง 0 และขอบ entity (ไม่เริ่มกลางที่ว่าง ไม่ต่ำกว่าขอบล่างกล่อง)
- [ ] ภาษาไทย: สระบน/ล่าง วรรณยุกต์ ไม่หาย ไม่ลอยไปบรรทัดอื่น (ดูคำว่า "ใบเข้าใช้", "ข้อมูล", "ที่ยืนยัน", "กีฬา"); `features.check('raqm')` ถ้าเป็น False generator ต้องพิมพ์ WARNING และใช้ตัวจัดสระในตัว
- [ ] เปิดรูป PNG ดูด้วยตา: ตัวอักษรไม่ถูกบัง ไม่มีกล่องขาวทับเส้น หัวตาราง ER มีสี
- [ ] เปิด .vsdx ใน Visio (หรือ LibreOffice `soffice --convert-to png`) อีกครั้ง เพราะ Visio วาด group ต่างจาก LibreOffice
- [ ] Level 1 อยู่หน้าเดียว process มีเลข entity พอดีข้อความ store วาดครั้งเดียว (ซ้ำได้ไม่เกิน 1 สำเนาเมื่อจำเป็น) store ที่ซ้ำมีขีดซ้ำทุกตัว
- [ ] ป้ายลูกศรอ่านออกเมื่อย่อลงขนาดในเล่ม

## C. ตรวจรูปเล่ม

- [ ] รูปแทนที่ใน .docx แล้ว ขนาด/ตำแหน่งตามตารางใน `report-insertion.md`
- [ ] คำบรรยายรูปใต้รูป ตารางเหนือตาราง เลขต่อเนื่อง
- [ ] หัวข้อ x.y = 18 pt, x.y.z = 16 pt, ฟอนต์ TH SarabunPSK, ข้อความไทยมี cs flag
- [ ] ส่วนนำเลขโรมัน เนื้อหาเลขอารบิกต่อเนื่องทุกบท
- [ ] สารบัญ สารบัญภาพ สารบัญตาราง ตรงกับ PDF ที่ render ใหม่ (เทียบเลขหน้าทีละรายการ)
- [ ] คำศัพท์ตรงกันทั้งเล่ม (ดู `report-insertion.md` ข้อ 8)
- [ ] ไม่มีหน้าว่าง ไม่มีรูปหรือตารางตกขอบ

## D. ข้อผิดพลาดที่พบบ่อย (จากข้อเสนอแนะกรรมการ เขียนแบบทั่วไป)

| ข้อผิดพลาด | ที่ถูก |
|---|---|
| ชื่อโครงการไม่ตรงกันระหว่างปก บทคัดย่อ บทที่ 1 และ Context | ใช้ชื่อเดียว ทั้งไทยและอังกฤษ ทุกที่ |
| วัตถุประสงค์ยาว/หลายข้อเกินจำเป็น | เขียนให้วัดได้ เช่น "เพื่อออกแบบ..." และ "เพื่อพัฒนา..." |
| ขอบเขตรวมงานของหน่วยงานอื่น | หน่วยงานนอกระบบ (เช่น คลัง) เป็น External Entity หรืออยู่นอกขอบเขต |
| ไม่มีผู้ดูแลระบบ ใครเป็นคนบันทึก master | กำหนดผู้ใช้ที่บันทึกข้อมูลหลักให้ชัด และอยู่ใน Context |
| process เรียงไม่ตามลำดับการเกิดข้อมูล | Master → ค่าที่กำหนด → Transaction → Report |
| แยกสถานะเป็น process ("ส่งซ่อม", "ชำรุด") | 1 process ปรับสถานะ + ตาราง lookup |
| ชื่อ process ไม่เป็นวลีกริยา หรือไม่เป็นวิชาการ | "แจกจ่ายอุปกรณ์ให้ช่าง", "บันทึกการใช้งานและปรับสถานะอุปกรณ์" |
| มีการแจ้งเตือนตามเกณฑ์ แต่ไม่มีที่กำหนดเกณฑ์ | เพิ่ม process กำหนดเกณฑ์ + store |
| ER หลายชุด / รวมตารางคนละเรื่อง / ไม่ตรงกับ store | ER ชุดเดียว แตกจาก store แยกเรื่องให้ชัด |
| ไม่อธิบายโครงสร้างองค์กร (ทีม โซน หัวหน้า) | อธิบายในบทวิเคราะห์ + นิยามศัพท์ |
| ผูกสิ่งของกับสถานที่ ทั้งที่ผู้รับผิดชอบคือคน | ผูกกับผู้ถือครอง (FK ไปพนักงาน) |
| คำเรียกไม่สม่ำเสมอ ("เสีย"/"ชำรุด") | เลือกคำเดียวทั้งเล่ม |
| ไม่มี Level 2 ของ process ที่ซับซ้อน | ทำ Level 2 เฉพาะ process หลายขั้นตอน |
| หัวข้อขนาดไม่ตามแบบ ส่วนนำไม่ใช่เลขโรมัน | 18/16 pt, โรมันในส่วนนำ |
| บรรณานุกรมผิด (ชื่อผู้แต่ง ปี ครั้งที่พิมพ์ URL) | ตรวจกับต้นฉบับจริงทุกรายการ ใช้รูปแบบของมหาวิทยาลัย |

## E. ข้อผิดพลาดที่พบจากการทดสอบกับ AI ตัวอื่น (ระบบจองสนามกีฬา, 5 พ.ย. 2569)

AI อีกตัวติดตั้ง skill แล้วใช้ generator ของเรากับระบบใหม่ ผลที่ผิดและวิธีที่ skill ป้องกันตอนนี้:

| ที่เห็นในรูป | สาเหตุจริง | ตอนนี้ป้องกันอย่างไร |
|---|---|---|
| Context: ลูกศรขาออกไป ผู้จัดการ เริ่มกลางที่ว่างใต้กล่อง 0 (เส้นลอย) | วาง entity ที่ y = 6.6 แต่กล่อง 0 สูงถึงแค่ 6.5 จุดต่อจึงอยู่นอกขอบ (fraction > 1) generator รุ่นเก่าไม่ตรวจ | generator ขยายกล่อง 0 ให้ครอบทุกเส้น และ error ถ้าปลายเส้นไม่อยู่บนขอบ; check_vsdx FAIL "not on the boundary" |
| Level 1: D1–D5 ถูกวาดซ้ำข้าง process ทุกตัว (19 กล่อง) | ใช้ layout แบบเดิม `store_order` (store ข้าง process) ที่ทำไว้ให้เล่มระบบอะไหล่ | ค่าเริ่มต้นใหม่ `store_mode: single`: store ละ 1 กล่อง ลากเส้นเข้า ซ้ำได้ไม่เกิน 1 สำเนาเมื่อจำเป็น (v3.2: 8 กล่อง เส้นตัด 0 ไม่มี line jump; 3 สำเนาคือน้อยที่สุด) |
| v3.2 preview column-rails: ซ้ำ entity ฝั่งซ้าย 8 กล่อง, หัวลูกศรใหญ่ | ให้หน้าแคบ A4 จึงซ้ำ entity | v3.3: entity กล่องเดี่ยวเยื้องกัน เส้นรูป L ซ้อน (แบบรูปอ้างอิงของผู้ใช้) ไม่มีเส้นค่อม; หัวลูกศรเล็กเป็นค่าเริ่มต้น |
| Level 1 v3.1: เส้นตัด 5 จุดวาดเป็น line jump (เส้นค่อม) | ยอมให้ตัดแล้ววาดเส้นกระโดด ผู้ใช้ไม่รับ | v3.2: เส้นอ้อมซ้อนเป็นชั้น (กลุ่มกว้างอยู่คอลัมน์ไกลกว่า) สำเนาน้อยที่สุดที่ไม่ตัด; build error ถ้า cross > 0; check_vsdx FAIL ทุกจุดตัด |
| สระ/วรรณยุกต์เพี้ยน: "ใบเขาใชสนาม", "ราย_ารฐนาม", วรรณยุกต์ลอย | Pillow บนเครื่องนั้นไม่มี libraqm (ขาด FriBiDi) จึงวาดแบบ BASIC วรรณยุกต์ของบรรทัดล่างไปโผล่ในบรรทัดบน (ทดสอบซ้ำได้ตรงกันทุกพิกเซล) | generator ตรวจ raqm ถ้าไม่มีจะเตือนและจัดสระ/วรรณยุกต์เอง; checklist บังคับเปิด PNG ตรวจ |
| รูปไม่มีข้อความผิดใน spec แต่รูปผิด | AI ไม่ได้เปิดดู PNG ก่อนส่ง | Workflow ข้อ 4: ต้องเปิดดูทุกรูป + check_vsdx ต้องผ่าน |

ตัวอย่างที่แก้แล้ว: `examples/booking/` (booking.json, png/, vsdx/)

## F. บทเรียนทางเทคนิค (ห้ามพลาดซ้ำ)

| ปัญหา | สาเหตุ | วิธีป้องกัน |
|---|---|---|
| กล่อง process ใน Visio เป็นสีขาวทึบ บังตัวอักษร/เส้น | group ใน Visio ค่าเริ่มต้น `DisplayMode = 2` วาดพื้นของ group ทับสมาชิก | ตั้ง `DisplayMode = 1` ทุก group + `FillPattern 0` / `NoFill 1` สำหรับ process store entity |
| หัวตาราง ER ไม่มีสีใน Visio (แต่ LibreOffice เห็นสี) | สาเหตุเดียวกัน พื้นขาวของ group ทับหัว | `DisplayMode = 1`, หัวเป็น shape ของตัวเอง `FillForegnd #BDD7EE` |
| LibreOffice render ดูปกติ แต่ Visio ไม่ปกติ | ตัววาดต่างกัน | ตรวจค่า cell ใน XML ด้วย `check_vsdx.py` ไม่ใช่แค่ดูรูป |
| ER มี 2 เส้นระหว่างคู่ตารางเดียวกัน | FK 2 ตัวไปตารางเดียว (prev/new) | วาดเส้นเดียว อธิบายใน DD; generator assert |
| กล่อง entity ยืดยาวเกินข้อความ | กำหนดความกว้างตายตัว | `max(1.6, textw + 0.4)` |
| กล่องตาราง ER สูงเกินจำนวนฟิลด์ | ตั้งความสูงเอง | สูง = RH × (ฟิลด์ + 1) |
| ข้อความไทยตัวหนา/ขนาดเปลี่ยนหลังแก้ | แทนข้อความข้ามหลาย run หรือ run ไม่มี cs | แทนเฉพาะคำใน run เดิม คง `<w:cs/>` szCs bCs |
| สารบัญเสีย dot leader | แทนข้อความทั้งเซลล์ | แก้ `w:t` ทีละตัว |
| สารบัญภาพเรียงผิด | เพิ่มรูปแล้วไม่จัดลำดับใหม่ | เรียงตามเลขภาพ ตรวจกับ PDF |
| หน้าว่างโผล่ | pageBreakBefore + page break ซ้อน | ใช้อย่างใดอย่างหนึ่ง |
| รูป ER สูงจนตกหน้า | ใส่ในหน้าแนวตั้ง | section แนวนอน กว้าง 8.30 in |
| Word เปลี่ยนชื่อ/ลำดับ media | Word renumber ตอนบันทึก | map rId → media จาก rels ทุกครั้ง |
| ความกว้างตาราง python-docx ไม่ตามที่ตั้ง | ไม่มี tblGrid / layout auto | ตั้ง gridCol + `tblLayout fixed` |
| คำถูกตัดบรรทัดกลางวลี | ช่องว่างธรรมดา | ใช้ NBSP (U+00A0) |
| เครื่องมืออ่านรูปแสดงรูปเก่า | cache ตามชื่อไฟล์ | ใช้ชื่อไฟล์ใหม่ทุกครั้งที่ตรวจด้วยตา |
| ลูกศรลอย ไม่ติดกล่อง | วาดเส้นเป็นรูปธรรมดา หรือจุดต่ออยู่นอกขอบกล่อง | ใช้ connector ที่ glue ทั้ง 2 ปลาย; `check_vsdx.py` ต้องผ่าน |
| วรรณยุกต์ไทยลอย/หายใน PNG | Pillow ไม่มี raqm | ตรวจ `features.check('raqm')`; generator มีตัวจัดสระสำรอง; เปิดรูปตรวจ |
| ผู้ใช้แก้ไฟล์ระหว่างที่ AI แก้ | ทับงานผู้ใช้ | ตรวจเวลาแก้ล่าสุดและไฟล์ล็อก `~$` ก่อนวางไฟล์ สำรองก่อนทับเสมอ แก้เฉพาะส่วนที่ได้รับมอบหมาย |
