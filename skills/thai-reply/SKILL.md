# ตอบเป็นภาษาไทยเสมอ

> ใช้กับ **ทุกงาน ทุกข้อความ ทุก session** และอ่านก่อน skill อื่น (รวมถึง dfd-er-design)

## กฎ

1. **ตอบผู้ใช้เป็นภาษาไทยทุกครั้ง** แม้ผู้ใช้พิมพ์ภาษาอังกฤษ พิมพ์ปนกัน หรือวางเอกสาร/ข้อความ error ภาษาอื่นมา
   - ข้อความแจ้งความคืบหน้า สรุปงาน คำถามกลับ คำอธิบาย error และรายงานผล ต้องเป็นภาษาไทยทั้งหมด
2. **ภาษาไทยที่เป็นธรรมชาติ สุภาพ กระชับ** เขียนแบบที่คนไทยพูดกันจริง ไม่แปลตรงตัวทีละคำจนแข็ง
3. **สิ่งที่คงรูปเดิม ไม่แปล**:
   - โค้ด คำสั่ง ชื่อไฟล์ path ชื่อตัวแปร/ฟังก์ชัน URL ให้อยู่ใน code span (`` `...` ``) หรือ code block ตามต้นฉบับ
   - ข้อความ error / log ให้ยกมาตามต้นฉบับทุกตัวอักษร แล้วอธิบายความหมายและวิธีแก้เป็นภาษาไทย
   - ศัพท์เทคนิคที่ใช้กันทั่วไป (API, database, commit, DFD, ER ฯลฯ) ใช้ทับศัพท์ได้; ศัพท์ที่ไม่คุ้นให้ใส่คำอธิบายภาษาไทยในวงเล็บ
   - ชื่อเฉพาะ (ชื่อคน บริษัท ผลิตภัณฑ์ เครื่องมือ) ใช้ตามเดิม
4. **ข้อยกเว้น**: ถ้าผู้ใช้สั่งชัดเจนให้เขียน "ผลงาน" เป็นภาษาอื่น (เช่น อีเมลภาษาอังกฤษ บทคัดย่อภาษาอังกฤษ)
   ให้เขียนตัวผลงานนั้นเป็นภาษาที่สั่ง แต่ข้อความที่คุยกับผู้ใช้รอบ ๆ ผลงาน (อธิบาย ถาม สรุป) ยังเป็นภาษาไทย
5. **comment ในโค้ด** ใช้ภาษาเดียวกับที่โปรเจกต์ใช้อยู่แล้ว; ถ้าโปรเจกต์ยังไม่มีแบบแผน ใช้ภาษาไทยได้

## ตรวจก่อนส่งทุกครั้ง

- [ ] ข้อความทุกส่วนที่ผู้ใช้อ่าน (ยกเว้นผลงานที่ผู้ใช้สั่งให้เป็นภาษาอื่น) เป็นภาษาไทย
- [ ] โค้ด คำสั่ง path ชื่อไฟล์ URL และข้อความ error ที่ยกมา ไม่ถูกแปลหรือแก้
- [ ] อ่านแล้วเป็นธรรมชาติ สุภาพ กระชับ ไม่เหมือนแปลด้วยเครื่อง
